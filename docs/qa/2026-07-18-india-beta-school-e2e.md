## Findings

- **S-001 - First cold onboarding render delay:** see Evidence Log step 1. Re-evaluate under a production build before treating it as a release defect.
- **S-002 - Duplicated School onboarding:** the generic and canonical School onboarding flows overlap, increasing form burden and making the intended journey unclear.
- **S-003 - Setup-to-placement handoff is non-deterministic:** one fresh run saved setup but left the learner on the review step while claiming it was opening the next step; a later clean control run did auto-route. The handoff must be made deterministic and visibly pending rather than relying on an eventual client transition.
- **S-004 - Choice controls have broken pointer semantics:** native browser control automation cannot click the visible radio/card controls; keyboard activation works.
- **S-005 - Form accessibility warning:** browser reports form fields without `id` or `name` attributes.
- **S-006 - Answer turnaround is incompatible with a child teaching loop:** multiple open-answer transitions remained in `Checking your answer` for around 90--120 seconds; at least one exceeded a 180-second observer window. The UI has no bounded pending, save-and-return, or retry state during that wait.
- **S-007 - Feedback lacks actionable evidence:** generic success/failure copy does not identify the passage detail, criterion, or misconception that explains the result.
- **S-008 - Open-answer grading is not yet trustworthy enough for progression:** a response containing both the literal sandbag image and a teamwork interpretation was marked `Not yet`; only a later response closely tracking the expected contrast/style was accepted. The child sees no criterion-level reason for the rejection.
- **S-009 - Lesson progress does not reflect learner work:** `00 / 07` persisted through support and masterclass work. It may be internally correct if those are pre-level activities, but it is misleading in the learner UI.
- **S-010 - Class-4 language is too abstract in key moments:** stage and prompt labels such as `Co Construct` and `Transfer the poetic-image skill` describe an instructional framework rather than a child-understandable task.
- **S-011 - Learner and parent reports make unsupported claims:** after only the observed readiness work and in-progress first chapter, the UI reported strong/improving skills and 5/12 transfer-check counts unrelated to the live lesson. The expanded record also surfaced stale or generic curriculum-memory skills. This is a release blocker because parents are being shown evidence-style assertions that do not trace to the learner's actual history.
- **S-012 - Target-ready placement dead-ends after its full evidence budget:** the clean control learner supplied strong, passage-grounded answers through all 18 available questions. The final report nevertheless stated that more evidence was needed, that no learning path was assigned, and that no more useful questions existed. This blocks a target-ready learner from reaching the Class 4 curriculum and is a release blocker.
- **S-013 - Placement's time contract is false in the live browser:** the screen promises about eight minutes, but repeated simple open-answer items each took roughly two minutes to move through `Reviewing your answer`. The control journey required the full 18 questions, creating a session duration incompatible with the stated expectation and with a child-facing product. Deterministic or locally rubric-scored items must not take the expensive evaluator path.
